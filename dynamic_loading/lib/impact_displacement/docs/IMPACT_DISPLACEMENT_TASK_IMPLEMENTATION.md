# 碰撞位移算法任务实现文档（Windows 先行版）

## 1. 目标与原则

本任务以“先在 Windows 环境完成算法框架与验证，再移植到 MCU”为主线，目标是建立可迭代、可验证、可移植的工程路径。

实施原则：
- 先定义数据契约与验收标准，再迭代算法细节。
- 先保证可测可复现，再优化精度与性能。
- PC 侧和 MCU 侧共享同一套核心接口，降低移植成本。
- 第二阶段以“事件后上传”为准，不要求实时计算与实时全量透传。
- 业务侧即使不关心方向，算法内部仍保留三轴向量积分，业务主输出可只消费位移标量。
- 旋转相关仅作为风险提示与信息性质量指标，不作为 v0 功能前置条件。

### M4：两板 RF store-and-forward 打通（按 `RF_EVENT_LINK_SPEC`）

- 交付：远端采集板事件缓存 + 网关重组 + PC 落盘/回放入口（可生成 CSV）。
- 验收：丢包/乱序下仍可重组完整事件或给出明确失败原因；事件号/分片序号一致。
- 风险：RF 丢包导致上传不完整；缓解：分片位图 + 按需重发。
- 风险：事件缓存溢出；缓解：事件窗上限 + 溢出告警/丢弃策略。
- 风险：协议字段演进；缓解：版本号字段 + 向后兼容解析策略。

## 7. 验收标准（Definition of Done）

功能维度：
- 输入输出接口稳定，状态机行为可预期。
- 算法能在 Windows 上稳定处理事件样本并输出结果。

质量维度：
- 关键异常场景有对应质量降级机制。
- smoke test + 至少一组回放测试通过。
- `disp_mm` 与 `confidence/quality_flags/rotation_error_mg` 的语义边界清晰，业务侧可据此做分级使用策略。

工程维度：
- 文档齐全（API、原理、任务实现、移植指南）。
- 版本可追踪（接口版本字符串可见）。

## 8. 风险与应对

风险 1：边界假设被破坏（大旋转、非静止后窗）
- 应对：质量评分降级并提示旋转风险；必要时引入陀螺仪融合。

风险 2：触发滞后导致前窗缺失
- 应对：预触发回溯机制；强制保留 `T_pre`。

风险 3：内存预估与实际偏差
- 应对：分离“事件缓存”与“算法工作区”预算，分别验证。

风险 4：参数敏感导致场景泛化差
- 应对：回放数据集驱动调参与版本化管理。

风险 5：RF 分片上传存在丢包或乱序
- 应对：事件号 + 分片序号 + 完整性校验（如 CRC/分片位图）；必要时增加重发策略。

风险 6：业务误把低可信 `disp_mm` 当作高可信物理位移
- 应对：文档明确 `confidence/quality_flags/rotation_error_mg` 的解读方式；业务侧按 `confidence` 分级使用。
