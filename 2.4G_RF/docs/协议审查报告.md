## 3. 与当前实现一致的关键点

### 3.1 帧模型与载荷布局

- `adhoc_frame.h` 定义 `ADHOC_FRAME_CONTENT_LEN=24`，帧总长 `32`。
- `adhoc_sm` 对 A 帧写入 `LMT_A(4B)`；`adhoc_data_plane` 对 D 帧写入 `LMT_D(3B)+Source(4B)+User(17B)`。
- `adhoc_data_ack_payload_pack` 使用每条 `7B`（`ID+LMT_D`）打包，单帧上限 `3` 条。

### 3.2 组网确认语义（Flag=7）

- 网关/已确认节点收到下级请求（`flag 0..5`）后，确认列表入队统一转为 `flag=7`。
- 子节点在 `U1/UN` 仅当收到“当前上级路径 + `flag=7` + 自身ID”才转 `C1/CN`。
- `flag=6`（已确认上级）在接收路径仅作为方向合法性信息，不触发入网确认跃迁。

### 3.3 组网窗口与状态机行为

- 网关角色在 `adhoc_sm_poll` 中：
  - 启动窗口：`gateway_network_started=1`
  - 到期锁定：`gateway_network_locked=1`
  - 锁定后停止组网广播发送
- 信标角色具备：
  - `ST1 -> U1/UN -> C1/CN` 主路径
  - 超过 `3*T5` 未收到当前上级 A 帧回退 `ST1`
  - `retry_count >= retry_max` 回退 `ST1`

### 3.4 数据面与链路观测

- 去重与 ACK 命中统一按 `source.node_id + LMT_D`。
- 转发队列支持 `T5` 周期重发、ACK 命中清理、重试耗尽报告。
- 链路适配层已加入 `TX busy` 保护（busy 时跳过 `start_rx`），并暴露 `busy/skip/error` 统计。
- LED 已加入窗口结束提示：网关 `gw_start=1 && gw_lock=1` 时“三连闪”。
- run11（`build/tmp/run11_final_retry_probe_20260506_192336/`）已命中 `retry_max=30` 路径：板2观测 `rpk=30/lrex=30/rex=11` 并多轮回退 `ST1`。
- run12（`R1~R4`）已完成四板轮换复核：`1GW+3BCN` 条件下复现窗口开闭、入网确认增长与窗口关闭后停增。

## 4. 当前有效差距（非过期项）

### 4.1 验证覆盖差距（高优先级）

1. **多网关场景仍缺实板闭环**  
   Windows 仿真已覆盖 `2GW + 多级 + 网状` 的协议逻辑，能够证明 `Top-K`、方向锁定、三级转发与压力路径在理想化信道中成立；但四板单网关轮换之外，`2GW+N BCN` 在真实 RF 链路下仍缺板测闭环证据。

### 4.2 协议高级语义收口差距（中优先级）

1. **`source_id_flag` 的多上级完整语义未完全收口**  
   当前实现采用“绑定号精确路径”策略，主路径可用，但多上级扩展语义仍需进一步定义与多板验证。

2. **全网统一绝对结束时刻/全局重组网策略未完全落地**  
   当前为可用的本地窗口与回退策略，已满足现阶段联调，但“全网统一结束对齐”仍待后续协议策略收口。

### 4.3 工程层说明（低优先级）

- `lib/Ad-Hoc-lib/include/adhoc_h.md` 明确标注为历史摘录，内容保留旧常量（如 `user[18]`、`ACK=4`），不应作为当前接口依据。当前接口以 `.h` 实头文件与本报告为准。
- run11 使用了测试场景构造（`ADHOC_TASK_GATEWAY_T2_US_OVERRIDE` + 临时确认丢弃宏）；常规构建必须保持测试宏关闭，避免污染日常联调结论。

## 7. 增量审查结论（2026-05-07）

### 7.1 新增板测证据

- 接线：`COM8=GW1`、`COM3=节点1(BCN)`、`COM11=GW2虚拟串口`，节点2仅上电。
- 复位方式：`GW1` 走 OpenOCD `reset run`，`GW2` 走 `COM11` 文本命令 `GW2RST`。
- 证据文件：`logs/node1_verify_20260507_165750.log`。
- 关键结果：
  - 节点1出现 `ST1 -> U1 -> C1`。
  - 节点1数据确认从 `sub=1/141, ack=2` 增长到 `sub=34/175, ack=74`。
  - `rex=0`，本轮未命中“重试耗尽导致上报失败”。

### 7.2 观测口径收口

- 网关侧 `adhoc data sub/ack` 在当前实现中是“本节点数据提交与确认统计”，不用于判断“子节点是否被确认”。
- “节点数据上报闭环是否成立”应以节点侧统计为准：`data sub` 与 `ack` 是否增长。
- 基于上述口径，本阶段“可入网 + 可确认 + 可持续上报”结论成立。

## 8. Windows 仿真增量审查结论（2026-05-11）

### 8.1 审查来源

- 设计基线：`lib/Ad-Hoc-lib/docs/软件设计文档.md`
- 仿真入口：`lib/Ad-Hoc-lib/test/README.md`
- 回归记录：`lib/Ad-Hoc-lib/test/验证与回归清单.md`

### 8.2 可接受结论

- 场景一/二与状态机覆盖表表明：`ST1/U1/UN/C1/CN` 主状态、`flag=7` 入网确认、多级入网与数据转发路径符合当前设计预期。
- 场景三/七表明：多网关候选、方向锁定、三级混合拓扑与多跳转发在 Windows 仿真环境中可运行，说明协议层逻辑并无明显结构性缺陷。
- 场景四/八表明：`3*T5` 上级失效回退、`regroup_interval_us` 本地重组网回退、`retry_max=30`、高频数据与长时间运行路径均可达。
- 场景六/八表明：在当前静态队列容量下，`16` 节点与高频数据场景未暴露明显的协议层队列溢出或状态机震荡问题。

### 8.3 接受边界

- 上述结果可接受为“协议层/状态机/数据面”的补充证据。
- 上述结果**不能**替代真实板级与 RF 链路证据，因为仿真环境不覆盖：
  - `AROS-RF` 的 `TX busy/start_rx` 竞争
  - 真实无线碰撞、时钟漂移、TMOS 调度抖动
  - 多频点/信道切换、真实 RSSI 波动与板级复位节拍

### 8.4 收口判断

- 当前“多网关逻辑是否成立”的问题，已可在协议层范围内回答为“成立”。
- 当前剩余高优先级缺口已收缩为“多网关实板闭环是否与仿真一致”，而不是“协议本身是否缺失实现”。
