# 碰撞位移估计算法的数学原理讲解

## 1. 文档目的

本文档用于解释“基于加速度事件窗估计短时位移”的数学基础，回答以下几个核心问题：

- 为什么理论上可以由加速度得到位移。
- 为什么原始加速度不能直接二重积分。
- 为什么不能把加速度合直接当成位移。
- 为什么需要前窗静止段、后窗静止段和终点速度约束。
- 为什么在没有陀螺仪辅助时，旋转会显著破坏结果。
- 为什么采用流式处理并不会改变数学结果。

本文档只讨论数学原理，不约束具体代码实现形式。

## 2. 变量与符号

设事件窗共有 `N` 个样本，索引为 `k = 0 ... N-1`。

- `t_k`：第 `k` 个样本的时间戳
- `dt_k = t_{k+1} - t_k`
- `a_raw[k]`：传感器输出的原始三轴加速度向量
- `a_dyn[k]`：去除静态重力和静态偏置后的动态加速度
- `a_mag[k]`：动态加速度模长，定义为 `|a_dyn[k]|`
- `a_corr[k]`：做完终点速度约束修正后的加速度
- `v[k]`：速度向量
- `x[k]`：位移向量
- `disp`：最终位移标量，定义为 `|x[N-1] - x[0]|`
- `g_hat`：由前窗静止段估计得到的重力加速度和静态偏置合成向量
- `b_res`：事件窗内残余常值偏置估计

如果输入单位为 `mg`，应先换算到 `m/s^2`：

`a_mps2 = a_mg * 9.80665 / 1000`

## 3. 理想物理模型

在理想情况下，若某一坐标轴上的线性加速度为 `a(t)`，则：

- 速度是加速度的一次积分  
  `v(t) = v(t0) + ∫ a(t) dt`

- 位移是速度的一次积分  
  `x(t) = x(t0) + ∫ v(t) dt`

因此位移等于加速度的二重积分：

`x(t) = x(t0) + v(t0)(t-t0) + ∫∫ a(t) dt dt`

这也是“用加速度估计位移”在理论上的基础。

## 4. 为什么原始加速度不能直接二重积分

MEMS 加速度计输出的不是纯粹的线性加速度，而更接近：

`a_meas(t) = a_lin(t) + g_body(t) + b(t) + n(t)`

其中：

- `a_lin(t)`：真正与平移运动相关的线性加速度
- `g_body(t)`：重力在传感器坐标系下的投影
- `b(t)`：零偏、温漂、低频漂移
- `n(t)`：高频噪声

如果不处理这些项而直接积分，误差会迅速积累。

### 4.1 偏置误差为何危险

假设只有一个很小的常值偏置 `b = 10mg`：

- `10mg ≈ 0.098 m/s^2`

若事件窗长度 `T = 0.5s`，则：

- 速度误差约为  
  `v_err = b * T ≈ 0.049 m/s`

- 位移误差约为  
  `x_err = 0.5 * b * T^2 ≈ 0.0123 m ≈ 12.3 mm`

这说明即使偏置很小，也足以在短时间内引入毫米到厘米级位移误差。

### 4.2 重力泄漏为何更危险

若姿态改变，重力在传感器坐标系下的投影会变化。  
如果我们错误地把某个固定的 `g_hat` 从整段数据中减掉，就会把“姿态变化引起的重力投影差”误当作线性加速度。

这类误差通常比普通零偏更大。

## 5. 本算法成立的前提

为了让问题在没有陀螺仪的条件下仍然可解，我们使用如下事件场景约束：

- 事件很短。
- 事件前后存在近似静止段。
- 事件以平移为主。
- 旋转角度较小。

在这些假设下，可以近似认为：

- 事件前窗中的均值代表“重力 + 静态偏置”
- 事件开始速度约为 `0`
- 事件结束速度也约为 `0`

这就是后续所有修正的数学基础。

## 6. 前窗静止段为什么能估计重力与偏置

设前窗静止段中物体基本不动，则其线性加速度近似为 `0`，此时：

`a_meas_pre[k] ≈ g_body_pre + b_pre + n[k]`

对前窗静止段做鲁棒平均，可得：

`g_hat = mean(a_pre_clean)`

这里的 `g_hat` 实际上不是纯重力，而是：

`g_hat ≈ g_body_pre + b_pre`

它是“重力投影 + 静态偏置”的合成估计量。

然后对事件窗中每个样本做去基线处理：

`a_dyn[k] = a_raw[k] - g_hat`

如果事件中姿态变化不大，且偏置变化慢，那么 `a_dyn[k]` 就近似等于真实线性加速度。

### 6.1 可选：动态重力估计（EMA）

当事件窗较长，或发生“轻微倾角变化”（例如桌面推移、线束拖拽）时，固定 `g_hat(pre)` 会引入重力泄漏：

`a_dyn(t) = a_meas(t) - g_hat(pre) ≈ a_lin(t) + (g_body(t) - g_body(pre)) + ...`

其中的 `(g_body(t) - g_body(pre))` 会被误当成线性加速度并参与积分，导致位移被显著高估。

一种工程上常用的折中是：在事件窗内用指数滑动平均（EMA，低通）去跟踪 `g_hat[k]`，并用它做去基线：

- EMA 更新：
  - `g_hat[k] = g_hat[k-1] + alpha_k * (a_raw[k] - g_hat[k-1])`
  - `alpha_k = dt_k / (tau + dt_k)`
  - `tau` 为时间常数（秒），越大表示越“慢”，越不容易被线性加速度牵着走。

- 动态加速度（高通效果）：
  - 为避免把当前样本的线性加速度直接“吸进” `g_hat[k]`，工程实现通常用上一时刻估计：
    - `a_dyn[k] = a_raw[k] - g_hat[k-1]`

说明：
- EMA 不是姿态解算，无法处理明显翻滚/大角度旋转；它只能缓解“小角度变化”导致的重力泄漏。
- `tau` 过小会把真实的低频线性加速度也当成重力的一部分，从而低估位移。

## 7. 离散积分公式

实际系统中我们只有离散样本，因此要把连续积分改成离散积分。

### 7.1 一次积分得到速度

用梯形积分法：

`v[k+1] = v[k] + 0.5 * (a[k] + a[k+1]) * dt_k`

其中初值通常设为：

`v[0] = 0`

如果采样周期固定，则 `dt_k = dt`。

### 7.2 二次积分得到位移

继续对速度做梯形积分：

`x[k+1] = x[k] + 0.5 * (v[k] + v[k+1]) * dt_k`

其中初值通常设为：

`x[0] = 0`

最终位移向量为：

`d = x[N-1] - x[0]`

位移模长为：

`|d| = sqrt(dx^2 + dy^2 + dz^2)`

### 7.3 为什么不能直接积分加速度模长

很多时候业务并不关心方向，只关心“撞了多远”或“动作有多大”，这很容易让人想到直接使用：

`a_mag[k] = |a_dyn[k]|`

再对它做一次或二次积分。这个思路看起来简单，但它不再对应真实净位移。

原因 1：模长会抹掉符号信息。

若某一轴存在一个理想对称事件：
- 前半段 `a_dyn = +a0`
- 后半段 `a_dyn = -a0`

则真实向量位移可能因为正负抵消而接近 0，  
但 `|a_dyn|` 在整个事件中始终为正，因此对 `|a_dyn|` 积分只会不断增加，不可能表达“回到原点”。

原因 2：模长不能保留向量几何关系。

业务虽然不关心最终方向，但物理位移是否发生抵消，本质上仍取决于三轴向量关系。  
如果先把向量压成标量，再去积分，就已经失去了恢复净位移所需的信息。

因此：
- 物理位移标量的正确计算方式是：先对三轴有符号加速度做向量积分，再对最终位移向量取模。
- `a_mag[k]` 更适合构造“运动强度代理量”，而不是物理位移。

## 8. 为什么还需要终点速度约束

仅仅做前窗基线扣除仍然不够，因为：

- `g_hat` 只是估计值，不是精确值
- 偏置可能在事件窗中仍有残差
- 采样噪声在积分后会累加

因此第一次积分后，通常会得到一个非零的终点速度：

`v_end = v[N-1]`

但从场景假设出发，若事件前后均静止，则真实速度应满足：

`v_true_start ≈ 0`

`v_true_end ≈ 0`

于是可以认为这部分 `v_end` 主要是残余偏置造成的。

## 9. 终点速度约束修正的推导

假设去基线后的加速度仍然含有一个近似常值残余偏置 `b_res`：

`a_dyn(t) = a_true(t) + b_res`

对整个事件窗积分：

`v_end = ∫ a_dyn(t) dt = ∫ a_true(t) dt + ∫ b_res dt`

若事件真实起止速度都近似为 `0`，则：

`∫ a_true(t) dt ≈ 0`

因此：

`v_end ≈ b_res * T_event`

于是可得：

`b_res ≈ v_end / T_event`

这就是文档中修正公式的来源。

然后对整段加速度做线性修正：

`a_corr[k] = a_dyn[k] - b_res`

再重新积分，就能使终点速度显著接近 `0`。

这个修正的物理含义是：

- 假设剩余误差主要是低频、近似常值的加速度偏置
- 用“终点速度必须回零”这个边界条件，把它反解出来

它不是任意拍脑袋的经验项，而是来自一个明确的边界约束。

## 10. 为什么旋转会破坏这个模型

如果物体在事件中发生明显旋转，则：

`g_body(t)` 不再近似常量

真实模型变成：

`a_meas(t) = a_lin(t) + g_body(t) + b(t) + n(t)`

而我们减去的是前窗固定估计值：

`a_dyn(t) = a_meas(t) - g_hat`

若 `g_hat ≈ g_body(pre) + b_pre`，则：

`a_dyn(t) ≈ a_lin(t) + [g_body(t) - g_body(pre)] + [b(t) - b_pre] + n(t)`

中括号里的

`g_body(t) - g_body(pre)`

就是“重力泄漏项”。  
它看起来和线性加速度没有任何区别，因此在没有陀螺仪的情况下，算法无法把它和真实平移加速度分开。

### 10.1 小角度近似下的误差量级

若姿态变化角度为 `theta`（弧度），则重力方向变化引入的虚假加速度量级近似为：

`a_rot_err ≈ g * theta`

例如：

- `theta = 15deg ≈ 0.262rad`
- `a_rot_err ≈ 9.81 * 0.262 ≈ 2.57 m/s^2`

这相当于：

- `≈ 262mg`

这个量级已经足以严重污染碰撞位移估计。  
这也是为什么文档中要把“小旋转”写成适用边界。

## 11. 为什么要比较前后窗的重力向量

若前窗和后窗都静止，则可以分别估计：

- `g_start`
- `g_end`

如果没有明显姿态变化，则它们应接近：

`g_start ≈ g_end`

因此可定义一个旋转相关误差指标：

- 向量差形式  
  `RotError = |g_start - g_end|`

- 或夹角形式  
  `theta_rot = arccos( (g_start · g_end) / (|g_start||g_end|) )`

这个量越大，越说明事件伴随姿态改变，位移结果越不可信。

这就是 `q_rotation` 的数学依据。

### 11.1 如果业务只关心标量，正确做法是什么

业务不关心方向，并不意味着算法可以放弃向量积分。

正确顺序应为：
1. 用三轴向量形式估计 `a_dyn[k]`
2. 分别积分得到 `v_x/v_y/v_z`
3. 再积分得到 `x/y/z`
4. 最后计算

`disp = sqrt(dx^2 + dy^2 + dz^2)`

这样得到的是“净位移的标量表示”，而不是“动作强度的累计量”。

也就是说：
- 可以不输出方向分量给业务
- 但不能在算法内部过早把三轴信息压缩成模长

## 12. 为什么要始终保留预触发数据

设碰撞触发时刻为 `t_trig`。  
如果只从触发时刻开始保留数据，那么积分起点可能已经落在碰撞过程中，而不是静止段中。

这样会带来两个问题：

- 失去前窗静止段，无法可靠估计 `g_hat`
- 丢失碰撞早期加速度，导致积分起点截断

因此必须有：

- 持续滚动的原始环形缓冲区
- 触发后回溯提取 `t_trig - T_pre` 到 `t_end + T_post`

这不是纯工程技巧，而是数学上保证边界条件成立的必要条件。

## 13. 为什么流式处理不改变数学结果

很多人会担心：如果不把整段浮点数组都存下来，而是逐点处理，数学上会不会变？

答案是不会，只要：

- 输入样本顺序不变
- 使用的积分公式不变
- 需要的边界量和状态量被正确保存

那么流式处理和整段数组处理在数学上是等价的。

例如梯形积分只依赖：

- 当前样本
- 上一个样本
- 当前累计速度或位移

因此并不要求整段浮点波形常驻 RAM。

对本问题而言，更合理的做法是：

1. 原始事件窗以整数格式保存在环形缓冲区或事件缓冲区中。
2. 算法按顺序扫描原始样本。
3. 每次只保留少量中间状态量。
4. 必要时对同一事件原始缓冲区做第二遍或第三遍扫描。

这种做法只是内存优化，不改变数学原理。

## 14. 本算法本质上解决了什么，不解决什么

本算法能解决的：

- 短时、近似平移、前后近似静止的碰撞位移估计
- 小偏置、小噪声、小角度姿态扰动下的事件级位移估计

本算法不能从根本上解决的：

- 长时间惯导漂移
- 大角度旋转导致的重力泄漏
- 传感器饱和削顶
- 丢样、时间戳错误、严重触发滞后

因此它本质上是一个“受场景约束的短窗估计算法”，不是通用惯性导航解算器。

## 15. 与卡尔曼/姿态融合的关系

当前方案不依赖卡尔曼滤波也能成立，因为它主要依赖：

- 事件窗短
- 前后静止
- 旋转小

如果后续场景出现明显旋转，则需要额外姿态信息来估计 `g_body(t)`，此时可考虑：

- 陀螺仪
- 互补滤波
- Mahony / Madgwick
- EKF 等姿态融合算法

这些方法的核心作用不是“让加速度更精确”，而是帮助估计姿态，从而更准确地分离重力项。

## 16. 结论

整套算法的数学逻辑可以概括为：

1. 用前窗静止段估计 `g_hat`，把原始加速度变成近似动态加速度。
2. 用离散积分把动态加速度积分成速度。
3. 用“事件结束速度应回零”的边界条件，反推出残余常值偏置。
4. 修正后再次积分，得到更可信的位移。
5. 用 `q_stationary`、`q_v_end`、`q_rotation` 等指标判断这次结果是否可信。

所以，这个算法不是“盲目二重积分”，而是“带物理边界条件的受约束短窗积分”。

补充结论：
- 若业务只关心位移标量，仍应先做向量积分，再取最终位移模长。
