# 自组网协议验证与回归清单（v0.1）

## 1. 目的

本文档将 `docs/设计文档（初稿）.md` 第 9 节“一致性核对清单”转为可执行验证项，作为 `T10` 的最小入口。

当前策略：

- 先保证“可观测、可构建、可联调”。
- 再逐项补齐板侧联调记录与主机侧/脚本侧验证。
- 若某项暂时只能人工验证，必须明确观测点与通过标准。

## 2. 验证分层

### 2.1 构建验证

- 命令：`xmake`
- 命令：`xmake f -m release && xmake`
- 目标：确认默认主路径可在 `debug/release` 下稳定构建。

### 2.2 板侧运行观测

- 观测入口：`serial_upload_task`
- 观测入口：`display_task`
- 观测入口：`tmos_led_task`
- 目标：确认 `ad_hoc_task`、链路适配层与数据面具备统一状态源。

### 2.3 协议行为验证

- 观测对象：组网消息 `A`、数据消息 `D`、网关确认、数据确认、重试回退。
- 目标：确认协议细节与 `docs/智能巡查系统自组网协议-003.pdf` 一致。

## 4. 当前联调入口

### 4.1 串口日志

- `uplink stat ...`：传感器快照摘要
- `adhoc stat ...`：协议主状态摘要
- `adhoc data ...`：数据提交与确认结果
- `adhoc link ...`：链路层 busy/fail/RSSI/TC 观测
- `adhoc sm ...`：状态机运行态观测（`st/lvl/retry/up_gw/up_no/up_age/gw_left/gw_lock/net_left`）

### 4.2 OLED

- 角色/域号/网关号
- 节点 ID
- `TX/RX`
- `SUB/ACK`
- `LNK busy/error`

### 4.3 LED

- 基于 `ad_hoc_task` 的 `rx_cnt`、`tx_report_acked`、`data_submit_ok` 活跃度判定链路存活。

### 4.4 单板验证记录（2026-04-26）

- 条件：`1` 块板、串口 `COM8/115200`、网关角色。
- 操作：烧录当前 debug 固件后，连续读取串口约 `40s`。
- 结果：
  - `adhoc sm` 中 `gw_left` 持续倒计时，并在约 `30s` 后归零。
  - `gw_lock` 由 `0` 翻转为 `1`，表明网关组网窗口已关闭。
  - `tx` 与 `link tx req` 计数在 `gw_lock=1` 后停止增长，符合“时间窗到期停发 `A V=0`”预期。
- 结论：当前已具备网关侧 `T07` 时间窗停发的单板硬件证据；信标锁定、多网关、上级失效回退仍待双板/多板继续板测。

### 4.5 双板验证记录（2026-04-26）

- 条件：板1为网关、板2为 `RF_TG_ID=1` 信标，仅观测板2 `COM3/115200`。
- 结果：
  - 板2从 `ST1` 进入 `C1`：`st=3`、`lvl=1`、`up_id=1`、`net_act=1`。
  - `adhoc data ack` 从 `4` 增长到 `11`，同时 `tx/rx` 计数持续增长，说明最小入网与数据上报 ACK 闭环已跑通。
  - 随后板2又回退到 `ST1`：`st=1`、`up_id=0`、`net_act=0`。
- 结论：
  - 可确认“最小入网 + 数据 ACK”主路径已具备真实双板证据。
  - 回退现象与“连续 `3*T5` 未收到上级 `A` 帧则回退 `ST1`”一致，但因本轮未同步采集板1侧状态，仍需后续复核其直接触发原因。

### 4.6 双串口复核记录（问题定位，2026-04-26）

- 条件：同时观测板2 `COM3` 与板1 `COM8`。
- 结果：
  - 板2复位窗口内可短暂进入 `C1`，随后再次回退 `ST1`。
  - 板1串口可确认 `role=GW`、`gw_lock=1`，并观测到链路层统计 `tx=16 / tx_req=477 / busy=461`。
- 结论：
  - 当前回退现象更偏向“网关侧有效广播过稀，超过 `3*T5` 后触发板2上级失效回退”。
  - 后续应优先排查 `adhoc_link_aros` / AROS-RF 发送 busy 原因，而不是继续把问题归因于 `T07` 状态机条款缺失。

### 4.7 双串口复核记录（修复验证，2026-04-26）

- 修复项：
  - 在 `app/adapters/adhoc_link_aros.c` 的 `adhoc_link_aros_start_rx_impl` 增加 `TX busy` 保护：`arf_isTxBusy()!=0` 时跳过 `RxStart`，并累计 `start_rx_skip_txbusy_cnt`。
- 结果（窗口开启阶段，历史 after-fix 采集）：
  - 板1：`gw_lock=0`，`tx=183 / tx_req=185 / busy=2`（busy 显著下降）。
  - 板2：`ST1 -> C1`（`st=3`、`up_id=1`），`adhoc data ack` 从 `0` 连续增长到 `10`。
- 结果（窗口关闭阶段，run2 同步采集）：
  - 板1：`gw_lock=1`，`tx=494 / tx_req=497 / busy=3`，广播处于关闭后稳定态。
  - 板2：保持 `ST1`，`ack` 维持 `18` 不再增长，符合“组网窗口关闭后不再新入网”预期。
- 结论：
  - 旧问题（高 busy 导致间歇失联）已被定位并得到轻量修复验证，当前 `T07` 可进入“继续补测多网关/多信标策略”的阶段。

### 4.8 双串口复核记录（run7 复位节拍验证，2026-04-26）

- 条件：
  - 采集方式：双串口自动重连采集（run7），板2=`COM3`，板1=`COM8`。
  - 复位节拍：先复位板2，约 `3s` 后复位板1。
- 结果（板1，网关）：
  - 先出现串口重枚举：`COM8` 在日志中可见 `FileNotFoundError` 后自动重连。
  - 重连后进入新一轮时间窗：`gw_lock=0, gw_left=29030ms`。
  - 约 `30s` 后窗口关闭：`gw_lock=1, gw_left=0ms`，同时 `tx=497/508, busy=11`，仍保持低 busy 稳态。
- 结果（板2，信标）：
  - 复位后统计归零：`tx=0, rx=0`，随后重新进入组网。
  - 可见 `ST1 -> C1`：`st=3, lvl=1, up_id=1`。
  - `ack` 从 `1` 持续增长到 `28`，随后随窗口结束回到 `ST1` 并停止继续增长。
- 结论：
  - “顺序复位 + 自动重连采集”流程可稳定复现，`T07` 的“窗口开启可入网、窗口关闭停入网”行为再次得到双串口证据。
  - run7 期间发现串口脚本在 Windows `GBK` 控制台下可能触发 `UnicodeEncodeError`，已在 `scripts/serial_reader.py` 增加安全输出回退，避免采集中断。

### 4.9 双串口复核记录（run8 复位节拍验证，2026-04-27）

- 条件：
  - 采集方式：双串口自动重连采集（run8），板2=`COM3`，板1=`COM8`。
  - 复位节拍：先复位板2，约 `3s` 后复位板1。
- 结果（板1，网关）：
  - 可见串口重枚举（`ClearCommError` + `FileNotFoundError`）后自动恢复。
  - 重连后重新进入时间窗：`gw_lock=0, gw_left=29031ms`。
  - 约 `30s` 后回到窗口关闭：`gw_lock=1, gw_left=0ms`，链路统计 `tx=500/505, busy=5`，保持低 busy。
- 结果（板2，信标）：
  - 复位后先清零再入网：`tx=0, rx=0` -> `ST1 -> C1(st=3, up_id=1)`。
  - `ack` 从 `2` 增长到 `24`，随后回到 `ST1`，符合窗口切换阶段行为。
  - run8 中统计到 `st3=20`、`st2=2`，说明存在短暂重试态但主路径可持续恢复。
- 结论：
  - run8 与 run7 结论一致：`T07` 的“窗口开启可入网 + 窗口关闭停入网”在双串口与顺序复位条件下可重复复现。
  - 串口脚本兼容性修复继续有效：run8 两路 `.err` 均为空，未再出现 `UnicodeEncodeError` 中断。

### 4.10 双板阶段收口（2026-04-27）

- 已完成（双板可完成项）：
  - 网关时间窗闭环：`gw_lock=0 -> gw_lock=1` 可重复复现（run7/run8）。
  - 信标方向行为：`ST1 -> C1 -> ST1` 可重复复现，且窗口阶段 `ack` 持续增长。
  - 上级失效回退：已观测到 `ST2` 短暂重试与回退 `ST1`，并有板1同步日志可对齐。
- 仍待后续：
  - `30` 周期重试上限的“可稳定触发样例”尚未固化，保留后续补测。
  - 多网关取舍与三板以上转发路径验证仍需更多板卡。

### 4.11 双串口复核记录（run9 重试路径探测，2026-04-27）

- 条件：
  - 采集方式：双串口自动重连采集（run9），板2=`COM3`，板1=`COM8`。
  - 操作：采集启动后仅复位板1（OpenOCD `reset run`），不复位板2。
- 结果（板1，网关）：
  - 再次完整复现时间窗：`gw_lock=0, gw_left=29031ms` -> `gw_lock=1, gw_left=0ms`。
  - 窗口关闭时链路统计 `tx=503/505, busy=2`，保持低 busy。
- 结果（板2，信标）：
  - 观测到重试路径活跃：`ST2(retry=3)` -> `C1` -> `ST1` -> `ST2(retry=5)`。
  - 本轮 `ack` 由 `52` 增至 `60`，说明窗口开启阶段仍可持续完成数据确认。
  - 本轮未命中 `retry=30`，最大观测重试计数为 `5`。
- 结论：
  - 双板已可稳定复现“重试路径存在 + 回退路径存在 + 窗口闭环存在”。
  - `30` 周期上限验证已进入“目标已明确、触发样例待固化”阶段。

## 5. 下一步建议
