# 碰撞前后位移估计算法分析与实现方案（仅文档评审版）

## 1. 目标与边界

本文档用于明确“基于加速度二重积分估计碰撞事件短期位移”的可落地方案，当前阶段只定义算法与库设计，不涉及具体代码实现。

配套数学原理说明见：
- `docs/IMPACT_DISPLACEMENT_MATH_PRINCIPLES.md`

目标：
- 估计单次碰撞事件在短时间窗口内的位移。
- 输出事件级位移结果与可信度，而非长期累计里程。
- 业务若不关心方向，可只消费位移标量，而不必消费方向分量。
- 适配当前项目任务模型（持续采样 + 阈值触发 + 环形缓存）。

边界：
- 不追求长期绝对位置。
- 不依赖 GNSS、UWB、视觉等外部定位。
- 在“碰撞前后存在静止段”的假设下工作。
- 适用于以平移为主、旋转角度较小的短时碰撞场景；若事件内姿态变化较大（建议超过约 `15deg`），结果可信度应显著降低。

## 2. 场景假设与关键结论

场景假设：
- MCU 持续采样三轴加速度，碰撞触发后提取“前窗+后窗”数据。
- 事件持续时间短（通常 100ms~800ms）。
- 事件前后存在近似静止段，至少可近似认为速度边界为 0。
- 事件内的主运动成分为平移；若同时存在明显翻滚或大角度偏转，则会出现重力泄漏误差。

关键结论：
- 直接二重积分（无约束）漂移很快，不可用。
- 必须使用“静止段约束 + 偏置校正 + 有限事件窗”的约束积分。
- 即使业务不关心方向，也应先做三轴有符号积分，再输出位移模长；不应直接把加速度模长积分成位移。
- 加速度模长或动态加速度模长更适合作为“运动强度代理量”，不应与物理位移混用。
- FIFO（后续上板阶段）有利于提高样本完整性与时序稳定性，但算法本身不强依赖 FIFO。
- 若无陀螺仪或姿态解算辅助，无法从根本上消除“大旋转导致的重力投影变化”误差，只能通过场景约束和置信度降级来控制风险。

## 3. 输入数据与采样要求

最小输入：
- 三轴加速度 `ax, ay, az`（带符号、线性单位，建议 mg 或 m/s^2）。
- 样本时间信息（固定 dt 或每点时间戳）。
- 事件窗口起止索引（含前窗、主碰撞段、后窗）。

建议采样率：
- 推荐 `fs = 400Hz`。
- 可接受 `fs = 200Hz`。
- `10Hz` 仅可用于“强弱指标”，不建议用于位移物理量。

建议量程：
- 冲击场景优先 `±8g` 或 `±16g`，避免饱和削顶。

## 4. 总体算法框架

算法主流程：
1. 事件窗口提取。
2. 原始数据预处理（单位换算、去异常、轻滤波）。
3. 重力与静态偏置估计（基于前窗静止段）。
4. 一次积分得到速度。
5. 速度终点约束（ZUPT）反推残余偏置并修正。
6. 二次积分得到位移。
7. 输出位移结果与质量指标（可信度评分）。

推荐采用“内部 3D 位移向量积分 + 外部位移模长主输出”方案：
- 算法内部保留 `dx/dy/dz`，用于正确处理符号与抵消关系。
- 业务主输出可只使用 `disp_mm`，不强制消费方向分量。
- 当事件质量较差时仍输出 `disp_mm`，但业务应结合 `confidence/quality_flags/rotation_error_mg` 解读，不应当作高可信物理位移。

## 5. 事件切窗策略

定义：
- 前窗：触发前 `T_pre`，用于估计静态偏置与重力方向。
- 主窗：触发到振动衰减阶段。
- 后窗：触发后 `T_post`，用于速度回零约束验证。

触发机制建议：
- 采样环形缓冲区必须持续滚动记录原始数据，而不是触发后才开始记录。
- 一旦触发，应能够回溯提取触发点之前完整的 `T_pre` 数据，避免因为门限触发滞后造成积分起点被截断。
- 对缓慢上升沿事件，建议加入“预触发（pre-trigger）”和短时峰值保持策略，保证碰撞起始段不会被漏掉。

建议初值：
- `T_pre = 150ms ~ 250ms`
- `T_post = 250ms ~ 500ms`

事件结束判据（建议组合）：
- 加速度模长回落到释放阈值以下并持续 `N_release` 点。
- 或事件持续时间达到上限 `T_event_max` 强制截断。

## 6. 预处理与校正

### 6.1 单位统一

若输入为 mg：
- `a_mps2 = a_mg * 9.80665 / 1000`

### 6.2 轻量滤波

建议：
- 2 阶低通（如 60~100Hz，取决于采样率和机械结构），抑制高频噪声。
- 不建议过强平滑，避免冲击峰值被明显削弱。

### 6.3 重力与偏置估计

建议做鲁棒估计：
- 先在前窗静止段上进行异常值剔除或中值预滤波，避免触发边缘的抖动污染静止基准。
- 再对清洗后的前窗样本求均值，得到 `g_hat = mean(a_pre_clean)`（向量）。

初始动态加速度：
- `a_dyn[k] = a_raw[k] - g_hat`

说明：
- 对短窗碰撞，前窗均值作为重力+静态偏置近似通常可行。
- 若事件时间较长或存在“轻微倾角变化”（桌面推移、线束拖拽），固定 `g_hat` 容易产生重力泄漏，导致位移被显著高估；此时可考虑启用“动态重力估计（EMA）”（v0 已实现，默认关闭）。

#### 6.3.1 可选：动态重力估计（EMA）

动机：
- 固定基线 `g_hat(pre)` 假设事件窗内姿态不变。一旦发生小幅倾角变化，`g_body(t)` 在传感器坐标系下的投影会变化，造成“把重力变化误当成线性加速度”的误差（重力泄漏）。
- 在 PC 侧验证中，桌面水平平移 50cm 这类“慢动作 + 轻微倾角变化”场景，固定基线往往会把位移推到 1m 量级；启用动态重力估计后可显著改善。

做法（工程实现）：
- 在事件窗内用指数滑动平均（EMA，低通）估计 `g_hat[k]`：它追踪“慢变化的重力投影 + 慢偏置”，并被用于去基线。
- 配置项：`impact_disp_cfg_t.gravity_ema_tau_ms`
  - `0`：关闭（默认），与当前 v0 行为一致，使用固定前窗基线。
  - `>0`：开启，以 `tau`（毫秒）控制 `g_hat` 的更新速度，典型值 300~800ms。

注意：
- 这不是姿态解算，不能在“大旋转”场景下恢复物理意义，只是降低“小角度变化”造成的重力泄漏。
- `tau` 过小会把真实的低频线性加速度也吸收进 `g_hat`，导致位移被低估；因此 v0 默认关闭，仅建议用于 PC 侧验证和“慢动作”类样例对齐。

## 7. 约束积分（核心）

### 7.1 一次积分（梯形）

设 `dt = 1/fs`：
- `v[k+1] = v[k] + 0.5*(a_dyn[k] + a_dyn[k+1]) * dt`

初值：
- `v[0] = 0`

### 7.2 终点速度约束修正

理想短窗事件常满足：
- `v[end] ≈ 0`

对每个轴估计残余常值加速度偏置：
- `b_res = v[end] / T_event`
  
物理假设说明：
- 假设残余积分误差主要来自近似恒定的零偏或低频偏置，因此采用线性修正；若误差主要来自姿态快速变化或强非线性噪声，该修正能力会明显下降。

修正加速度：
- `a_corr[k] = a_dyn[k] - b_res`

然后重新积分得到 `v_corr`，理论上 `v_corr[end]` 接近 0。

### 7.3 二次积分得到位移

- `x[k+1] = x[k] + 0.5*(v_corr[k] + v_corr[k+1]) * dt`
- `x[0] = 0`

结果输出：
- 位移向量 `d = x[end] - x[start]`
- 位移模长 `|d|`

### 7.4 为什么不建议直接用加速度合计算位移

不建议把 `|a_raw|` 或 `|a_dyn|` 直接做积分后当成位移，原因有二：

- 原始加速度模长包含重力项，姿态变化时会同时受到重力投影和线性加速度影响，缺乏明确物理可分离性。
- 即使先减去前窗基线，再取 `|a_dyn|`，也会丢失方向与符号信息，无法正确表达“先出去再回来”这类净位移抵消过程。

因此：
- 若要输出物理位移，即使业务不关心方向，也应先做三轴向量积分，再对最终位移向量取模。
- 若只想得到“这次撞击动作有多强”，应单独设计“强度指标”（例如 `∫|a_dyn(t)|dt`），而不是把它命名为位移。

## 8. 质量评估与置信度

建议输出以下质量指标：
- `q_stationary_pre`：前窗静止程度（方差/峰峰值）。
- `q_stationary_post`：后窗静止程度。
- `q_v_end`：修正后终点速度残差。
- `q_rotation`：事件前后重力向量一致性。
- `q_clip`：饱和样本比例。
- `q_missing`：丢样比例。
- `q_dt_jitter`：采样间隔抖动。

`q_rotation` 建议实现：
- 分别计算前窗和后窗静止段的 `g_start`、`g_end`。
- 定义 `RotError = |g_start - g_end|`，或进一步换算为夹角误差。
- 当 `RotError` 过大时，说明姿态发生明显变化，应显著降低 `confidence`。

最终可形成 0~100 的综合评分 `confidence`，并给出等级：
- A：高可信，可直接用于位移判定。
- B：可用，建议配合阈值裕量与质量标志位使用。
- C：低可信，仅用于趋势参考或调试定位，不建议当作高可信物理位移。

## 9. 参数建议（首版）

建议默认参数：
- `fs = 400Hz`
- `T_pre = 200ms`
- `T_post = 300ms`
- `T_event_max = 800ms`
- `trigger_high`：按实测噪声与工况设定（建议先做统计标定）
- `release_low`：低于触发阈值，防止迟滞震荡
- `N_release = 8 ~ 20`（取决于 fs）
- `fc_lpf = 80Hz`（400Hz 时）

## 10. 算法库设计（lib 层）

建议库名：
- `lib/impact_displacement/`

建议文件结构（规划）：
- `lib/impact_displacement/inc/impact_displacement.h`
- `lib/impact_displacement/src/impact_displacement.c`
- `lib/impact_displacement/src/impact_displacement_filter.c`（可选）
- `lib/impact_displacement/test/`（后续）

建议 API（草案）：
- `impact_disp_get_version()`：返回算法库版本信息，便于联调与固件追踪。
- `impact_disp_get_default_cfg(cfg)`：获取默认参数。
- `impact_disp_init(ctx, cfg)`：初始化。
- `impact_disp_reset(ctx)`：复位状态（保留 cfg）。
- `impact_disp_begin_event(ctx, event_id)`：进入事件采集状态（流式接口）。
- `impact_disp_set_baseline_mg(ctx, bx, by, bz)`：设置基线（通常来自前窗均值）。
- `impact_disp_feed_sample(ctx, sample)`：逐点喂入事件窗样本（流式处理）。
- `impact_disp_end_event(ctx, out)`：事件结束并输出结果（可在释放判据满足后调用）。
- `impact_disp_process_event(ctx, samples, count, pre_samples, event_id, out)`：批处理助手（PC 侧离线验证用）。
- `impact_disp_get_state(ctx)`：查询状态机状态（调试/联调用）。

建议输入结构：
- `timestamp_us`
- `ax_mg, ay_mg, az_mg`（或 m/s^2）
- `flags`（如饱和/丢样标志）

建议输出结构：
- `dx_mm, dy_mm, dz_mm`
- `disp_mm`（模长）
- `duration_ms`
- `peak_acc_mg`
- `terminal_speed_mm_s`
- `rotation_error_mg`
- `confidence`
- `quality_flags`

## 11. 资源评估（CH32V208 量级）

建议将内存评估拆成两部分：

事件原始数据缓存：
- 按 400Hz、事件总窗 1s 估算，样本数约 400 点。
- 每点若存 `int16 x3 + time_delta + flag`，约 10~12B。
- 单事件原始缓存约 `4~5KB`。

算法运行时工作区：
- 不建议开辟与事件长度等大的浮点数组来保存整段波形，否则 RAM 占用会迅速膨胀。
- 推荐采用“流式处理（streaming processing）”或“多遍扫描事件缓冲区”策略：从环形缓冲区读取原始样本 -> 逐点转换与积分 -> 仅保留少量状态量与最终结果。
- 在该策略下，算法额外工作 RAM 可控制在 `< 200B` 量级；但这不包含事件原始数据缓存本身。

运算复杂度：
- 主要为 O(N) 向量加减与积分，计算量可控。
- 若无硬件 FPU，可优先采用定点实现或“采样存整数、计算用 float”。

CPU 量级评估：
- 当前工程系统时钟配置为 `144MHz HSE`，事件级 O(N) 处理的实时性预期充足。
- 现阶段不建议在文档中写入未经实测的固定 CPU 占用百分比；建议在后续上板阶段用 GPIO 翻转或定时器统计方法实测单事件处理耗时，再反推 CPU 占用率。

## 12. 风险与缓解

风险 1：姿态变化导致重力分量误估。
- 缓解：缩短事件窗；加入后窗重力一致性校验和 `q_rotation` 指标；若无陀螺仪辅助，超过小角度旋转边界时应直接降级结果可信度；必要时引入姿态估计（后续）。

风险 2：冲击饱和削顶导致位移低估。
- 缓解：提高量程，记录饱和标志并降低置信度。

风险 3：阈值误触发导致非碰撞事件。
- 缓解：触发与释放双阈值 + 最短持续时间 + 形态判据。

风险 4：采样抖动与丢样。
- 缓解：使用时间戳积分；引入 `q_dt_jitter/q_missing`。

风险 5：业务误把低可信事件的 `disp_mm` 当成高可信物理位移。
- 缓解：在接口与文档中明确 `confidence/quality_flags/rotation_error_mg` 的解读方式；业务侧按 `confidence` 做分级使用策略。

## 13. 验证计划（先离线后上板）

阶段 A：离线回放验证
- 用已采集事件窗数据在 PC 端回放。
- 对比不同参数组（阈值、窗长、滤波）稳定性。
- 指标：重复性（同工况方差）、鲁棒性（噪声下漂移）。

阶段 B：半实物在线验证
- 板端只输出原始事件窗与算法中间量。
- PC 端计算位移，快速迭代参数。

阶段 C：板端闭环
- 将算法下沉到 MCU，输出位移与置信度。
- 验证 CPU 占用、内存占用、事件吞吐。

## 14. 分阶段落地建议

第 1 阶段：定义数据契约
- 统一样本格式与事件窗结构。
- 约定质量标志位与错误码。

第 2 阶段：库骨架与离线一致性
- 建立 `lib/impact_displacement` 空实现与测试入口。
- 先对齐离线与板端浮点/定点结果一致性。

第 3 阶段：参数固化与协议对接
- 增加位移结果上报字段。
- 增加调参项（窗长、阈值、滤波参数）。

## 15. 可作为评审结论的简版摘要

- 该场景适合“事件窗约束积分”方案。
- 核心不是普通二重积分，而是“前窗重力估计 + 终点速度约束修正 + 再积分”。
- 采样率应提升至 200Hz 以上，推荐 400Hz。
- 即使业务不关心方向，也不应直接用加速度模长积分成位移；应先做向量积分，再输出位移标量。
- 输出必须包含置信度与质量标志位，避免把低质量事件当成真实位移。
- 建议在 `lib` 新建独立算法库，先离线验证后上板集成。
